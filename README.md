# New Here frontend

Expo SDK 57 / React Native app. Use Node 24 (the CI version), then `npm ci` and `npm start`.

## Environment

Copy `.env.example` to `.env` and set the Supabase project URL, public key, and `EXPO_PUBLIC_API_BASE_URL`.
The older `EXPO_PUBLIC_SUPABASE_ANON_KEY` name is also supported. Never use a service-role key in the app.
For an Android phone, the API URL must be your computer's reachable LAN address, for example
`http://10.78.179.193:8000`; `localhost` on the phone refers to the phone. Restart Expo after environment changes.
The FastAPI service in `../backend` needs its own environment and database migrations. Browser requests
also require CORS configuration on that service; native requests do not.

## Email confirmation and recovery

Supabase Authentication → Providers → Email must have **Confirm email** enabled.
Authentication → URL Configuration → Redirect URLs must include the URLs for the runtime you use:

- Installed/development builds: `newhere://auth/callback` and `newhere://auth/callback?type=recovery`.
- Expo Go: allow the running project's URL, for example `exp://10.78.179.193:8081/--/auth/callback**`.
  Use the same host and port as the Expo Go project. Update this entry when the LAN IP or port changes.
  Keep Metro running and open the email on the phone running that project.
- Web: allow `http://localhost:8081/auth/callback**` for that development port and your actual deployed
  HTTPS origin's `/auth/callback**` for production. The website must serve the SPA for this route.

The app generates an `exp://` callback in Expo Go, `newhere://` in installed builds, and the current
origin on web. Expo Go does not register `newhere://`. Changing code cannot change an email already
sent: reload the app and request a fresh email from **Resend confirmation email**. If an earlier link
already confirmed the account, simply sign in. Confirmation links are single-use.

Use Supabase's default confirmation URL in email templates (`{{ .ConfirmationURL }}`), so its verify
endpoint validates the email before redirecting to the app. The callback establishes the session from
returned access/refresh tokens and also supports PKCE code exchange. Errors and expired links show a
recovery screen; password recovery links open the new-password form. Do not log or share email tokens.

References: [Supabase mobile deep links](https://supabase.com/docs/guides/auth/native-mobile-deep-linking),
[Expo linking](https://docs.expo.dev/linking/into-your-app/).

## Onboarding

Authenticated users go through welcome → how it works → personalization → daily home.
On app entry, the client reads its own `user_preferences` record using the existing Supabase RLS
policy. A profile with first/last name, birth date, and city ID skips onboarding across restarts/devices.
A profile read failure shows retry/sign-out controls instead of silently restarting setup.

Personalization posts to `POST /api/v1/users/onboarding` using the actual backend schema:
`first_name`, `last_name`, `date_of_birth` (YYYY-MM-DD), `latitude`, `longitude`, optional
`place_name`/`place_country`, and deduplicated backend interest categories. Interests are optional.
The form validates real dates and required fields; searching after selecting a location clears that
selection. Denied GPS permissions leave manual place search available. The UI navigates only after
successful submission and reloads the persisted profile. Backend migrations 001–004 provide this flow.

## Verification

- `npm run lint` — zero warnings allowed.
- `npm run typecheck` — TypeScript, including route types generated by Expo.
- `npm test -- --ci --runInBand` — email/date validation, callback session handling, profile completion,
  and authenticated API/error handling regression tests.
- `npx expo export --platform web` — production web bundle.

The pre-commit hook runs lint, typecheck, and tests once, stopping on the first failure. CI uses Node 24.
On a fresh checkout, Expo generates typed routes on `npm start`; generated `.expo` files are not committed.

For a device smoke test: sign up, open the newest email on the phone, confirm return to onboarding,
complete personalization, restart and confirm arrival at daily home. Test expired links, resend, and
password recovery as well. Live delivery and database writes require the configured Supabase/backend.
